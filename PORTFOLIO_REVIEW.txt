================================================================================
                    4. CRITICAL BUGS IDENTIFIED
================================================================================

BUG #1: ProjectService Constructor Typing Error (CRITICAL)
File: backend/src/services/project_service.py:8
Issue: Method named __int__ instead of __init__
Impact: ProjectService cannot be properly instantiated with dependencies
  def __int__(self, project_repository: ProjectRepository):  # WRONG
  def __init__(self, project_repository: ProjectRepository):  # CORRECT

BUG #2: Incorrect JSON Response Format
File: backend/src/controllers/auth_controller.py:24
Issue: jsonify() called with tuple instead of proper format
Impact: Response format is incorrect, may cause client-side parsing errors
  return jsonify({"message": "Login successful!", "token": token}, 200)  # WRONG
  return jsonify({"message": "Login successful!", "token": token}), 200  # CORRECT

BUG #3: JWT Token Extraction Inconsistency
File: backend/src/controllers/project_controller.py:10-14
Issue: Token extracted without removing "Bearer " prefix
Impact: Authentication will fail on protected routes
  token = request.headers.get('Authorization')  # Includes "Bearer " prefix
  # Should strip "Bearer " prefix like project_type_controller.py does

BUG #4: decode_jwt Returns user_id but Auth Store Expects Different Format
File: backend/src/utils/jwt_utils.py:24 vs client/src/store/auth.ts:14
Issue: Backend returns user_id from 'sub' claim, but auth store checks response.data[1]
Impact: Authentication flow is broken

BUG #5: Multiple Base Declarations
File: backend/src/models/user.py:4 vs backend/src/models/database.py:22
Issue: User model declares its own Base instead of using database.Base
Impact: SQLAlchemy may create duplicate tables or relationship failures

BUG #6: Inconsistent Token Handling in Auth Store
File: client/src/store/auth.ts:14-19
Issue: Checking response.data[1] === 401, but Flask returns JSON with status code separately
Impact: Authentication error handling is incorrect

                      5. SECURITY CONCERNS
================================================================================

CRITICAL:
1. CORS wildcard (*) allows any origin - should be restricted
2. ~~JWT secret key printed to console in auth_service.py:22~~ (FIXED)
3. ~~Password hash printed to console in auth_service.py:16~~ (FIXED)
4. No rate limiting on login endpoint
5. No CSRF protection
6. Debug mode enabled in production (main.py:85)
7. Default user credentials in environment variables (potential exposure)

HIGH:
1. No input sanitization on project creation endpoints
2. No file type validation in media upload (only checks 'file' in request)
3. Temporary files saved to /tmp without cleanup
4. No HTTPS enforcement
5. No Content Security Policy headers

MEDIUM:
1. No token refresh mechanism
2. No session invalidation on logout (token remains valid until expiry)
3. No password complexity requirements
4. Email stored in plaintext

                      6. PERFORMANCE ANALYSIS
================================================================================

ISSUES:

1. LARGE IMAGE ASSETS
   - Multiple PNG images (DEONE_1.png through DEONE_11.png, etc.)
   - No image optimization or lazy loading
   - No WebP format conversion
   - No responsive image sizes

2. UNOPTIMIZED BUNDLE
   - All Bulma CSS imported (should use tree-shaking)
   - Font Awesome loaded via CDN (should be bundled or use icons)
   - DevIcons loaded via CDN
   - No code splitting configured

3. MISSING CACHING
   - No service worker caching strategy (only registration)
   - No HTTP cache headers configured
   - No CDN for static assets

4. DATABASE QUERIES
   - No pagination on project listing
   - No database indexing on frequently queried fields
   - No connection pooling configuration

5. NO LAZY LOADING
   - All components loaded eagerly
   - No route-based code splitting
   - No virtual scrolling for project lists
